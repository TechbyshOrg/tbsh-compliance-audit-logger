Compliance Audit Trail & Evidence Logger

The Compliance Audit Trail & Evidence Logger is an enterprise-grade security monitoring, cryptographic verification, and audit-readiness logging platform designed for WordPress. Aligned with strict cybersecurity regulations (including NIS2, DORA, SOC 2, and ISO 27001), this plugin goes beyond typical activity logs by providing legally defensible, tamper-evident audit records.

Legally Defensible Records

Every system transaction is cryptographically chained together using SHA-256 signatures, making unauthorized modifications or deletions immediately evident to security auditors.

Core Pillars & Features

  • Tamper-Evident Chaining: Standard database records can be easily modified or deleted directly via SQL. This plugin hashes each entry with the hash signature of the preceding log record, establishing an unbroken cryptographic chain.
  • Archival Evidence Vault: Automatically or manually capture full-system configuration snapshots (installed plugins, active themes, user roles, security configurations, database capacities) to serve as proof of system integrity during compliance audits.
  • GDPR Privacy Shield: Client IP addresses and User Agents are hashed locally and irreversibly using HMAC-SHA-256 with a unique, cryptographically random site salt. Complete support for core WordPress Personal Data Exporters and Erasers is included.
  • No Cloud Dependency: Built for high compliance. All log events, audit timelines, verification records, and snapshots are kept locally in custom SQL tables. No telemetry data or user footprints are ever offloaded.

Getting Started & Installation

Follow these steps to deploy the plugin on your WordPress instance:

  1. Upload the tbsh-compliance-audit-logger directory to your WordPress site's /wp-content/plugins/ folder.
  2. Log in as an Administrator and activate the plugin through the Plugins page in the WordPress admin panel.
  3. Navigate to the new Compliance Logs sidebar menu to access the verification status, timeline, logs grid, and vaults.
  4. Go to Settings to customize logging thresholds, automatic evidence vault snap frequencies, and log retention parameters.

System Requirements

  • WordPress version 6.2 or higher.
  • PHP version 8.0 or higher.
  • MySQL / MariaDB database with standard transactional locking support.

How Things Work (Lifecycle & Flow)

The lifecycle of a logged event is built to maximize server efficiency while guaranteeing absolute cryptographic integrity:

  1. Event Capture: The plugin hooks into specific WordPress core actions (like logins, theme swaps, profile updates, and plugin upgrades) inside EventTracker.php.
  2. Runtime Queuing: To avoid interrupting page rendering, the logged event is not immediately written to the database. Instead, it is appended to an in-memory runtime queue managed by Logger::$log_queue.
  3. Flushing at Shutdown: When WordPress triggers the PHP shutdown hook (meaning the page has completed loading and is rendered for the client browser), the queue is flushed.
  4. Sequential Chaining: During the database flush:
    • A lock is requested to prevent race conditions from concurrent sessions.
    • The verifier retrieves the signature hash of the last successfully logged event in the database.
    • The new row is inserted, and a combined canonical SHA-256 hash is computed using the record's values and the retrieved previous hash.
    • The row is updated with its calculated signature hash, making it an integral link in the cryptographic chain.

When Things Trigger (Timelines & Crons)

The plugin manages background events dynamically:

  • Plugin Activation: Automatically builds/upgrades SQL schemas, generates a secure 64-character site salt for privacy masks, sets default logging preferences, schedules the daily evidence snapshots cron, and registers the initial activation log event.
  • Plugin Deactivation: Cleans up scheduled cron tasks and logs a warning event.
  • Plugin Uninstallation: If configured in the admin dashboard (Delete All Tables and Settings), the plugin drops all three custom SQL tables, deletes options records, and clears scheduled crons permanently.
  • Daily / Weekly Background Task: A WordPress cron job (tbsh_cal_cron_job) executes every 24 hours (or weekly depending on settings) to compile system configuration snapshots and prune expired logs (if logs retention is set to a value greater than 0).
  • GDPR Request Completion: When a user personal data erasure request is completed, the data is anonymized immediately, and a chain rebuild is triggered from the first altered ID onwards.

Core Architecture & Developers API

The logging engine is accessible to third-party integrations, allowing custom tracking parameters to be injected directly.

Programmatic Logging API

Developers can trigger compliance-focused events programmatically using the static Logger::log() method:

PHP API Usage 
use TBSHComplianceAuditLogger\Logging\Logger;

Logger::log(
    'config_alteration',                 // event_type
    'Configuration Management',          // event_category
    'warning',                           // severity (info, notice, warning, error, critical)
    'Security Constant Modified',         // event_title
    'Constant WP_DEBUG was modified.',   // event_message
    [
        'object_type'     => 'configuration',
        'object_id'       => 'WP_DEBUG',
        'compliance_tags' => 'ISO 27001 A.12, NIS2 Art 21',
        'metadata'        => [
            'previous_value' => true,
            'current_value'  => false
        ]
    ]
);

On activation, the plugin deploys three optimized, indexed tables using the default database schema:

Cryptographic Hash Chaining & Verification

To protect records from unauthorized direct SQL manipulation, each database row is cryptographically linked to the previous row. A SHA-256 signature is calculated by combining row values with the preceding row's signature.

Canonical Hash String Structure

The verification engine compiles a canonical pipe-separated string from the database columns in the exact order below:

Hash Spec 
$canonical_string = implode('|', [
    $row_id,
    $row_uuid,
    $event_type,
    $event_category,
    $severity,
    $event_title,
    $event_message,
    $user_id,
    $site_id,
    $object_type,
    $object_id,
    $ip_hash,
    $user_agent_hash,
    $request_method,
    $request_uri,
    $metadata_json,
    $compliance_tags,
    $previous_hash,
    $created_at
]);

$integrity_hash = hash('sha256', $canonical_string);

Verification Logic

During an Integrity Scan, the verifier iterates through every log sequentially, recalculating the signature. If a row has been deleted, its ID sequence breaks, or if any cell is modified, the signature check fails immediately, flagging that specific ID and cascading failures down the rest of the trail.

GDPR Privacy Shield & Data Protection

Compliance logging requires recording the actor behind each event without violating strict data privacy laws. This plugin accomplishes this by employing irreversible local hash masking.

  • Salted Anonymization: IP addresses and User Agents are hashed locally using hash_hmac('sha256', $ip, $salt). The salt is generated on first activation using cryptographically secure random values and stored locally.
  • GDPR Exporter Integration: Registers the plugin with WordPress personal data exporters to gather all logging actions mapped to a user's email.
  • GDPR Eraser Integration: When personal data erasure is requested, the plugin anonymizes the actor columns (changing the username to "Anonymized User", user_id to 0, role to "none") and automatically rebuilds the cryptographic hash chain starting from that record to preserve audit trail integrity without breaking the chain.

Evidence Vault & State Archiving

The Evidence Vault acts as a configuration snapshot collector. It archives the technical system footprint at regular intervals or manual triggers to prove that the environment was secure and uncompromised at the time.

Archived System Footprint Payload

Component Group Technical Metrics Captured
Plugins & Themes List of all installed plugins and themes, versions, stylesheets slugs, and active/inactive status.
User Roles Definitions of all custom user roles and their associated capabilities mapping.
Database Status Exact table names, row counts, data storage sizing, collation sets, and SQL engines.
Security Context WordPress security constants (WP_DEBUG, script debugging, SSL enforcement), PHP version, and MySQL mode.
